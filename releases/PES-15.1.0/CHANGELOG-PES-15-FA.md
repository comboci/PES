# تغییرات PES-15.1.0 — تفکیک مراحل تسک (۲۰ نوامبر ۲۰۲۶)

- پنج مرحله مستقل برای هر Task: analysis، prioritization، implementation، verification، acceptance.
- نوع خروجی هر تسک با `workflow.deliverable_phase` مستقل از سایر مراحل مشخص است.
- انجام اولویت‌بندی یا تغییر رنگ/رتبه، هرگز به معنای اجرای اصلاح، تست یا تأیید نیست.
- تکمیل واقعی اجرا تنها با ارجاع به Evidence یا Source Revision ثبت می‌شود؛ انجام اجرا، تست و تأیید را نتیجه نمی‌دهد.
- راستی‌آزمایی و پذیرش نیازمند رکوردهای مستقل Verification و Acceptance با پیوند معتبر هستند.
- گزار‌ش‌گیری `task-status` و `retrieval.task_progress` وضعیت هر مرحله و نتیجه خروجی تسک را جداگانه نمایش می‌دهند.
- برای تسک‌های تاریخی بدون Workflow، وضعیت تمام مراحل «نامعلوم» است و از `status=completed` یا `priority` استنتاج نمی‌شود.
- ایجاد Workflow برای تسک‌های تاریخی و ارتقای نسخه PES-15.0.0 فقط با خروجی جدید و دستور صریح ممکن است.
- فایل‌ها، دیتابیس و مصرف‌کنندگان PES-14، نسخه اصلی PES-15.0.0 و سورس Portfolio Builder تغییری نکردند.
- کنترل بازگشایی مرحله موفق با دلیل، بدون حذف شواهد و با حفظ تاریخچه CAS.

# تغییرات PES-15 نسبت به PES-14

## P0 — اجرا شده در موتور مرجع

- استاندارد و Schema جدید `15.0.0` با هویت و Digest مستقل؛ هیچ‌کدام از فایل‌های نسخه ۱۴ بازنویسی نشده‌اند.
- ساختار ۱۵ دسته رکورد، Scopes، Retriever Contracts، Provenance و Validation لایه معنایی.
- کنترل یکتایی سراسری شناسه‌ها، روابط داخلی، سلسله‌مراتب Scope، تناقض‌های Open State و استثناهای Legacy.
- الزام اولویت برای Taskهای جدید و timestamp معتبر برای Observationهای جدید؛ حفظ مقادیر تاریخی نامعلوم.
- Typed Relationships با هدف داخلی یا هدف خارجی صریح و هشدار در مورد داده‌های خارجی تأییدنشده.
- مانع حذف رکوردها/Scopeهای تاریخی و دستکاری منشأ مهاجرت در Commit جدید.
- SQLite با تراکنش `BEGIN IMMEDIATE` و CAS روی Revision + SHA، تاریخچه append-only و هش زنجیره‌ای.
- بکاپ مستقل با Online Backup API و بررسی صحت زنجیره؛ عدم بازنویسی مقصد.
- مهاجرت اختیاری غیرمخرب از PES-14، بدون تغییر Contract پیش‌فرض تاریخی.
- بازیابی دانش با ردگیری منشأ، روابط و هشدارهای عدم قطعیت و تأییدنشده.

## P1 — در مرز پیاده‌سازی مرجع، هنوز نیازمند پذیرش عملیاتی

- آزمون روی آخرین فایل کامل PES-14 پروژه Portfolio Builder با Python (در محیط فعلی فقط آزمون اتصال نمونه نماینده و ممیزی read-only فایل کامل انجام شد).
- یکپارچه‌سازی CLI/API در کد Tauri/Windows برنامه؛ هنوز انجام نشده.
- تست مقدماتی دو Process و Rollback پس از قطع فرایند انجام شده؛ آزمون بار واقعی، قطع برق سخت‌افزاری، Benchmark و Security Audit باقی مانده است.
- اتصال live به GitHub برای تأیید واقعی Freshness/Source Revision؛ فعلاً عمداً «غیرتأییدشده» گزارش می‌شود.
- Adapter مناسب محیط چند ماشین و سیستم دسترسی/مجوزها، امضا/لنگر بیرونی برای log؛ خارج از دامنه موتور مرجع محلی.

**ورژن ۱۴ همیشه مستقل باقی می‌ماند و با نسخه ۱۵ جایگزین اجباری نمی‌شود.**
